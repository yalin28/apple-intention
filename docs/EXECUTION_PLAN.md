## 1. 目标与范围

根据归档视频 `reference/video/designed-by-apple-intention-1080p.mp4`（原附件名 `designed_by_apple_-_intention (1080p).mp4`），用 **Lenis + GSAP + ScrollTrigger** 制作一个鼠标滚动驱动的单页，最终交付一个 `index.html`。

- 忠实还原画面构图、英文原文、图形运动、黑白切换、场景顺序与转场关系。
- 向下滚动推进，向上滚动倒放；停止输入后只允许短暂惯性收敛，画面随后停在当前位置。
- 保留视频内部动作节奏，按阅读需要重新分配滚动距离。视频时间不是用户必须花费的浏览时间。
- 不处理音频。不得用播放视频、滚动修改视频 currentTime 或整片图片序列代替网页动画。
- 不添加与视频无关的导航、卡片、按钮、产品介绍、彩色装饰或鼠标跟随效果。
- 最终应用的样式、业务脚本、SVG 和绘图数据放在同一个 HTML 中。默认第三方库采用固定版本 CDN；因此是单 HTML 交付，但需联网加载依赖。若后续要求离线，改为内联已核对许可的库，保留许可声明，不增加应用资源文件。
- 原始视频只作为开发参考，不成为网页运行依赖。本文档属于交接资料，不计入应用文件数。

## 3. 视觉与表现原则

### 3.1 舞台与文字

原片以大面积浅灰白或近黑背景、居中的小字号文字、圆点与极细线条构成。文字是画面本身，不应改成网页常见的超大标题。38.75 秒附近 `feel?` 的突然放大属于特定动作，应保留。

- 使用 1920 × 1080 设计坐标，中心为 (960, 540)。文字及主体位置以参考帧归一化坐标记录。
- 桌面以完整构图为优先：16:9 内容舞台等比 contain 到视口中，余白沿用当前场景背景色。背景遮罩需要覆盖整个视口，不能只覆盖 16:9 内框。
- 浅背景、深背景、正文、细线各设基础颜色。初始可用浅灰白、带少量暖色的近黑作为估值，随后从原始分辨率参考帧取色；不得将估值标注为视频实测色值。
- 参考片有轻微底色不均匀与压缩纹理。先还原主体，不加动态噪点或大面积模糊来模仿压缩痕迹。
- 字体先使用 Helvetica Neue、Helvetica、Arial、sans-serif 回退，常规或较轻字重。最终对照原片校准字宽、字号、字距与基线，不声称已确认原字体。
- 主句保持原文、大小写与句末标点。按词组显示，只有确有逐字变化的地方拆字。避免让未出现的词造成整行居中位置持续跳动。
- 小屏保留完整几何关系，同时将正文设为可读字号，必要时按语义换行；明确小屏排版是适配，桌面 16:9 是还原基准。

### 3.2 分层与绘制方式

| 层 | 内容 | 首选技术 |
| --- | --- | --- |
| 背景 | 浅/深底色 | CSS 背景，少量状态变化 |
| 密集动态图形 | 粒子、景深点群、放射连线 | 单个 Canvas 2D |
| 少量清晰几何 | 开场多边形、圆环、双点连线 | 内联 SVG |
| 文字 | 英文原句、词组揭示 | DOM 文本 |
| 转场 | 斜向深色平面、黑/白大圆扩张 | CSS/SVG 几何层，优先 transform |

同一画面如有前后遮挡，可将少量前景粒子分离；没有实际遮挡需求不增加第二个全屏 Canvas。文字通常独立于缩放圆盘，避免圆盘扩张时字号跟着放大。圆盘内外文字切换按实际遮挡关系处理。

时间范围是连续的规划分组，不代表这些时刻都发生硬切。跨场对象应连贯移动，同一场内的多个文案必须分别标注进入、稳定、离开三个节点。

### 4.1 滚动节奏规则

1. 每场拆为进入、展示、离开三个区间。一般以 20% / 50% / 30% 起步；依据视频动作调整，不机械套用。
2. 完整句子的清晰可读窗口初定不少于 0.35H；`delight`、`surprise`、`love`、`connection` 等单词各不少于约 0.2H。窗口是滚动距离，不保证用户快速拖动时仍停留固定秒数。
3. 转场只占需要的距离；不为一秒纯空白分配与复杂动作相同的滚动长度。
4. 默认不开启吸附、整屏翻页、滚轮锁定。一次滚动可连续跨场；快速滚动必须直接得到目标位置的正确画面。
5. 原片弹性或加速只用于场内图形动作；总进度映射保持线性。慢滚时可观察动作中间态，反向时完整回退。
6. 31H 的总距离只通过场景权重统一调整，不能在多个位置同时改倍率。首轮若拖沓，先减少空白/重复运动，不压缩关键句阅读窗口。
7. 页面底部应正好停在落款，不再滚出一个空白尾屏。pin 占位与页面总高度只由一种方式管理，避免重复计入 31H。

## 5. 动画与滚动架构

### 5.1 单舞台、单主时间轴

使用自然文档滚动和一个视口舞台，由唯一主 ScrollTrigger 固定舞台。pin 的容器不参与位移/缩放，动画只作用于内部对象。保留默认 pin 占位机制，避免同时手工增加整段滚动高度。

总时间轴的逻辑长度设为 **31 单位**，每单位对应 1H 滚动距离。表中累计位置直接成为主时间轴标签位置，避免另加一套非线性时间换算层。各场内部保留视频相对动作节奏，再插入阅读停留。

子场景时间轴加入 master 后只由 master 驱动，不设置自己的 ScrollTrigger，不独立自动播放，也不采用无限循环。跨场对象的属性应有清楚归属，防止两个场景同时控制同一属性。

状态契约：给定主时间轴位置、视口尺寸和固定种子，输出画面必须确定。无论从开头走到该位置、从结尾倒回、直接拖动滚动条跳到该位置，都应得到同一状态。

### 5.2 Lenis 与 GSAP 的接线

采用 Lenis 官方 GSAP 集成模式：Lenis scroll 事件通知 ScrollTrigger.update；GSAP ticker 驱动 Lenis.raf，ticker 的秒转换为毫秒；关闭额外 autoRaf，使用官方建议的 lagSmoothing 设置。自然 window 滚动先不引入 scrollerProxy，也不叠加 ScrollSmoother。依据：[Lenis 官方文档](https://github.com/darkroomengineering/lenis#gsap-scrolltrigger)。

初始体验参数为本项目待验证设定：`smoothWheel` 开启、`lerp` 约 0.1、滚轮倍率 1；使用 lerp 时不同时依赖 duration 调速。主 ScrollTrigger 使用 `scrub: true`，先由 Lenis 提供平滑，避免再叠很长的 scrub 追赶时间。只有实测仍有必要时才试很短的数值 scrub，并记录停手收敛时间。

ScrollTrigger 的起点以舞台顶部到达视口顶部为准，终点为起点加 31H 的函数值；字体就绪与尺寸变化后刷新。保持一个主触发器，子场景使用时间轴标签，遵循 [ScrollTrigger 文档](https://gsap.com/docs/v3/Plugins/ScrollTrigger/) 与 [Timeline 文档](https://gsap.com/docs/v3/GSAP/Timeline/)。

### 5.3 初始化、反向与重建

- 顺序：准备静态首屏 → 加载并检查库 → 建立几何和确定性粒子数据 → 等字体就绪 → 建立时间轴与触发器 → 刷新尺寸 → 渲染当前位置。
- 在 JS 初始化前提供有效首屏或原文静态内容，避免白屏。库加载失败时显示简洁提示和可读内容。
- 初始状态集中设定。后续多次对同一属性使用 from/fromTo 时明确 immediateRender 行为，避免后场初态污染前场。
- 不在 onEnter/onComplete 中临时新增粒子、改文案、启动延迟动画或改变关键可见性。关键状态用时间轴插值或从绝对进度计算，保证反向与跳跃可靠。
- Canvas 的绘制由主时间轴更新触发，读取已更新的场景状态；尺寸或可见性改变时补绘一次，不另起持续 requestAnimationFrame。
- 视口变化时重新计算舞台缩放和 Canvas 像素尺寸；需要重建动画时保存逻辑进度、清理旧实例后恢复，避免重建后回到首屏。
- 使用稳定视口高度处理移动端工具栏变化，避免微小高度变化不断重算滚动总长；真正横竖屏切换时完整刷新。
- 页面恢复前台后同步位置并补绘，不按离开时长继续播放。事件监听与 ticker 回调须可移除，重建不叠加实例。

## 6. 图形与粒子的实现策略

### 6.1 少量几何

- 开场用 circle、line、polyline/path 组成线框组。绘制进度用描边偏移，组缩放/旋转用 transform。路径长度在初始化计算，不在每帧读取。
- 多边形与圆之间若需要连续变形，先统一采样点数量再插值，避免为少量基础形状引入 MorphSVG 等额外插件。
- 点沿线框运动采用预计算路径或可解析参数，不每帧查询大量 SVG 几何方法。
- 两圆交集可用 SVG mask 或清晰的几何区域构造；优先保障边界正确，不默认用重型滤镜制造粘连。
- `we simplify` 的线、圆点与 `we perfect` 的圆盘用少量路径关键状态实现；先补看过渡，再决定是否需要路径变形。
- 背景斜切使用超出视口的旋转平面；圆形全屏覆盖的最终半径至少达到圆心到视口最远角的距离，并留少量防缝余量。不要只依据屏幕宽度算终态。

### 6.2 密集点群

- 使用固定种子，只在初始化生成每个点的起点、目标点、大小、透明度、深度、延迟和轨迹参数。
- 每场局部进度通过插值、曲线和有限周期函数计算点位置，不采用依赖上一帧的速度积分。停止滚动后不继续运行背景粒子。
- 主点的路径与半径按视频人工校准；背景小点可用确定性分布近似。需要在交接中区分“关键点精校”和“背景点近似”，不能把随机相似当完整还原。
- `feel?` 到粒子阶段先加密抽帧，判断是文字采样散开还是点群替换。若需要文字点阵，只在初始化从离屏文字采样，缓存结果，不每帧读回像素。
- 景深先用缓存的软边圆点精灵与透明度表达，不对大量对象实时 blur。大而模糊的前景圆数量保持很少。
- `thousand no’s` 的文案不意味着必须绘制 1000 个节点；以参考画面密度为依据，初始预算可取约 250–600 个点，按实际效果校准。
- 放射结构每点最多连到一个中心节点，复杂度随点数线性增长；线条在场景退去时随进度消隐。
- 黑白切换时背景、点色、线色与文字颜色同一帧切换或按原片明确过渡，不让深色点暂时消失在深底。

## 7. 性能与适配标准

以下为验收目标；代码措施已实施，局部计算与绘图已检查，**浏览器交互、实际帧率和无障碍实际操作未测试**。具体证据见第 11 节。

| 方面 | 目标与方法 |
| --- | --- |
| 渲染 | 主要 DOM 动画使用 transform / opacity；SVG 描线与 Canvas 绘制属于必要绘制成本，不宣称全部由 GPU 合成 |
| 调度 | 一套 GSAP ticker，Canvas 仅在进度或尺寸改变时绘制；不在每帧创建 tween、数组、渐变或节点 |
| 绘制预算 | Canvas DPR 初始上限 2；高分辨率/低性能情形优先降至 1.5，再降低次要背景点数量，保留关键动作 |
| 图层 | 不给所有点设置 will-change，不创建数百 DOM 粒子；只对需要的少量变换层作提升 |
| 布局 | 尺寸与文字测量集中完成；滚动更新中不反复 getBoundingClientRect，不混杂布局读写 |
| 目标帧率 | 在明确记录的桌面环境以稳定接近 60fps 为目标；60Hz 的单帧预算约 16.7ms，优先避免应用引入的持续长任务 |
| 精细测量 | 获得浏览器验证授权后，检查粒子峰值场景的 scripting/painting、>50ms 长任务与明显掉帧；记录设备、分辨率、DPR 和实际结果 |
| 反向稳定性 | 反复跨越黑白转场、拖到中段、End 后 Home，画面无残影、漏场或旧粒子残留 |
| 适配 | 至少静态考虑 1920×1080、1440×900、1280×720、390×844；移动端原生触摸优先，不强制模拟桌面惯性 |
| 可访问性 | 保留键盘自然滚动；减少动态偏好下提供按顺序阅读的静态场景/原文，避免长时间固定与大幅缩放；装饰 Canvas/SVG 不重复进入朗读顺序 |

性能优化顺序：消除重复调度和每帧分配 → 缓存软点绘制 → 限制 Canvas 像素面积 → 减少次要点与边 → 调整视觉细节。不要先删掉视频最有辨识度的动作。

本项目用户规则：**只有用户明确要求浏览器测试、调试、检查或验证时，才使用本地浏览器控制工具。**当前请求是执行文档，不开展浏览器控制。后续代码阶段若没有新增浏览器验证授权，完成静态/局部检查并明确报告交互与帧率未实测，不把计划中的性能指标当作已通过结果。

| 问题 | 当前决策 | 何时调整 |
